# 03. 프론트엔드 구현 지침

## 1. 범위
Vanilla JavaScript로 화면 상태와 API 통신을 구현한다. 서버 비밀키나 AI 프롬프트를 프론트엔드에 두지 않는다.

## 2. 화면 상태
추천 영역은 다음 상태를 구분한다.
- `idle`: 아직 요청 전
- `loading`: 추천 요청 중
- `success`: 추천 결과 존재
- `empty`: 추천 결과 없음
- `error`: 요청 실패

피드백 영역은 별도로 다음 상태를 관리한다.
- 목록 `loading / success / empty / error`
- 제출 `idle / submitting / success / error`

한 영역의 오류가 다른 영역을 불필요하게 숨기지 않도록 한다.

## 3. 입력 검증
취향 입력:
- trim 이후 5~500자
- 빈 값이면 “원하는 장르나 분위기를 5자 이상 입력해 주세요.”
- 500자 초과면 “500자 이내로 입력해 주세요.”
- 서버에서도 동일한 검증을 다시 수행한다.

피드백:
- 이름은 선택, 최대 40자
- 내용 trim 이후 2~1000자
- 잘못된 입력이면 해당 필드 아래에 오류 표시

## 4. API 통신 계약
### POST `/api/recommend`
요청:
```json
{ "preference": "반전이 많고 어두운 한국 범죄 스릴러" }
```
성공 응답:
```json
{
  "recommendations": [
    {
      "rank": 1,
      "title": "작품명",
      "year": 2022,
      "genres": ["범죄", "스릴러"],
      "matchPercentage": 92,
      "reason": "사용자가 요청한 어두운 분위기와 반전 중심 전개가 취향에 맞습니다."
    }
  ],
  "scoreDescription": "백분율은 후보 작품 사이의 상대적 취향 매칭 점수이며 시청 만족도 확률이 아닙니다."
}
```
오류 응답:
```json
{ "error": { "code": "INVALID_INPUT", "message": "입력 내용을 확인해 주세요." } }
```

### GET `/api/feedback?limit=20&offset=0`
성공 응답:
```json
{
  "items": [
    {
      "id": "uuid",
      "displayName": "익명",
      "content": "추천 이유가 자세해서 좋았어요.",
      "createdAt": "2026-01-01T00:00:00.000Z"
    }
  ],
  "hasMore": false
}
```

### POST `/api/feedback`
요청:
```json
{ "name": "", "content": "추천 결과가 마음에 들었습니다." }
```
성공 응답:
```json
{
  "item": {
    "id": "uuid",
    "displayName": "익명",
    "content": "추천 결과가 마음에 들었습니다.",
    "createdAt": "2026-01-01T00:00:00.000Z"
  }
}
```

## 5. 렌더링 안전 규칙
- 사용자 입력, AI 응답, 피드백 내용은 `textContent`로 표시한다.
- 외부 문자열을 템플릿 문자열과 `innerHTML`로 삽입하지 않는다.
- DOM 요소는 `document.createElement`로 생성한다.
- 점수는 0~100 사이 정수로 제한된 값만 CSS 너비에 반영한다.
- 날짜는 브라우저에서 읽기 쉬운 형식으로 변환한다. 날짜 파싱에 실패하면 원문 대신 “날짜 정보 없음”을 표시한다.

## 6. 사용성
- 추천 요청 중 중복 제출을 막는다.
- 네트워크 오류 시 입력값을 유지하고 재시도할 수 있게 한다.
- 추천 요청 성공 후 결과 영역으로 스크롤 이동하는 것은 가능하나, 과도한 자동 스크롤은 피한다.
- 피드백 저장 성공 후 입력값을 비우고 새 항목을 목록 맨 위에 반영한다.
- “더 보기”를 누르면 offset을 증가시키고 기존 목록 뒤에 추가한다.
- API 응답이 예상한 형식이 아니면 안전한 일반 오류를 표시한다.

## 7. 완료/검증 기준
- API 성공/오류 응답을 올바르게 표시
- 요청 중 버튼 비활성화
- 추천 결과 0~3개 처리
- 점수 막대가 점수와 일치
- XSS 형태의 문자열이 실행되지 않고 텍스트로 보임
- 피드백 최신순 목록과 더 보기 동작
- 모바일 키보드 사용 시 입력/버튼 조작 가능
