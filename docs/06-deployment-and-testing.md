# 06. 배포, 환경 변수 및 검증 지침

## 1. 환경 변수
`.env.example`에는 이름만 작성하고 실제 값을 넣지 않는다.
```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```
- 실제 값은 로컬 `.env.local` 및 Vercel 프로젝트 환경 변수에 등록한다.
- `.env.local`은 Git에 커밋하지 않는다.
- `OPENAI_MODEL`은 사용할 수 있는 모델 ID를 명시적으로 설정한다.
- 환경 변수 누락 시 서버가 안전한 오류를 반환한다.

## 2. 로컬 실행
1. Node.js LTS 설치
2. `npm install`
3. `.env.local` 생성 후 환경 변수 입력
4. Supabase SQL Editor에서 `supabase/schema.sql` 실행(해당 파일을 프로젝트에 생성)
5. Vercel CLI로 로컬 개발 서버 실행
6. 브라우저에서 로컬 주소 접속
7. 추천/피드백 API 동작 확인

실제 `package.json` 스크립트와 설치 버전에 맞춰 README 또는 실행 안내를 작성한다. 문서에 없는 명령을 성공했다고 가정하지 않는다.

## 3. Vercel 배포
1. Git 저장소에 프로젝트 push
2. Vercel에서 저장소 Import
3. Framework Preset은 정적 사이트/Other에 맞게 설정
4. Root Directory 확인
5. Production/Preview/Development 환경별 환경 변수 등록
6. 배포
7. 배포 URL에서 API와 정적 페이지 확인
8. 로그에서 오류를 확인하되 비밀키가 출력되지 않는지 점검

## 4. 테스트 체크리스트

### 취향 입력/추천
- [ ] 빈 입력은 요청되지 않고 안내가 표시됨
- [ ] 4자 입력은 차단됨
- [ ] 5자 입력은 유효성 검사를 통과함
- [ ] 500자 입력 허용, 501자 입력 차단
- [ ] 정상 입력에서 최대 3개 추천 표시
- [ ] 순위가 1, 2, 3으로 표시
- [ ] 점수는 0~100 정수
- [ ] 각 결과에 추천 이유 표시
- [ ] 점수 설명에 상대 매칭 점수라는 의미 표시
- [ ] AI 결과 0개인 경우 빈 상태 표시
- [ ] AI 오류/시간 초과/잘못된 JSON 상태 표시
- [ ] 요청 중 중복 제출 방지

### 피드백
- [ ] 이름 없이 제출 가능
- [ ] 2자 미만 내용 차단
- [ ] 1000자 초과 내용 차단
- [ ] 이름 40자 초과 차단
- [ ] 제출 성공 후 목록 최상단에 표시
- [ ] 새로고침 후에도 데이터 유지
- [ ] 최신순 정렬
- [ ] 빈 목록 상태 표시
- [ ] DB 오류 상태 표시
- [ ] 더 보기 동작 및 중복 항목 없음

### 보안
- [ ] 브라우저 소스/네트워크 응답에서 OpenAI 키 확인 불가
- [ ] 브라우저 소스/네트워크 응답에서 service role 키 확인 불가
- [ ] 사용자 입력이 HTML/스크립트로 실행되지 않음
- [ ] API 서버 측 길이 검증 확인
- [ ] 메서드 오류와 잘못된 JSON 처리
- [ ] 서버 로그에 키/토큰이 없음

### 반응형/접근성
- [ ] 320px 모바일에서 가로 스크롤 없음
- [ ] 태블릿/데스크톱 레이아웃 확인
- [ ] 키보드만으로 입력/제출 가능
- [ ] 포커스 표시 확인
- [ ] 오류/로딩 메시지가 보조기술에 전달됨
- [ ] 점수 막대에 접근성 속성 존재

## 5. 완료 보고 형식
구현 완료 시 다음을 보고한다.
- 구현된 기능
- 생성/수정한 주요 파일
- 로컬 실행 방법
- 필요한 환경 변수 이름(값은 절대 출력 금지)
- 실행한 테스트와 결과
- 미완료 항목/외부 설정 필요 항목
- 배포 URL(실제 배포한 경우에만)

## 6. 최종 인수 조건
PRD의 체크리스트가 모두 충족되어야 한다. 실제 OpenAI 키와 Supabase 프로젝트가 제공되지 않은 경우, 에이전트는 코드/목업 테스트까지만 완료로 표시하고 실서비스 연동 검증은 미완료라고 명확히 보고해야 한다.
