# 02. UI 구현 지침

## 1. 디자인 목표
첨부 이미지의 핵심 특성인 흑백 대비, 굵은 글자, 단순한 도형감, 넓은 여백을 참고한다. 첨부된 “Out Of Order 2024” 로고를 그대로 복제하거나 서비스 로고로 사용하지 않는다.

## 2. 디자인 시스템
- 배경: 순백색 또는 아주 옅은 회색
- 기본 글자: 거의 검정
- 보조 글자: 중간 회색
- 테두리: 얇은 회색
- 강조: 검정색 단색 우선. 점수 막대도 검정/회색으로 표현
- 폰트: 시스템 산세리프 우선(`system-ui`, `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, sans-serif)
- 제목: 굵고 크게, 본문: 충분한 줄 간격
- 그림자/그라데이션/장식 아이콘은 최소화

## 3. 화면 레이아웃
### 상단
- 텍스트 로고 예시: `SCENE / PICK` 또는 `DRAMA INDEX`
- 로고는 새로 디자인하고 첨부 이미지의 상표/문구를 복사하지 않는다.
- 상단 내비게이션은 필수 기능이 없으므로 단순하게 유지한다.

### 히어로/입력
- 중앙 정렬된 큰 제목: “오늘, 어떤 드라마가 보고 싶나요?”
- 짧은 안내: 장르·분위기·소재·전개 취향을 자유롭게 작성
- 입력 textarea는 넓고 충분한 높이로 구성
- placeholder는 구체적인 예시를 제공하되 입력값으로 자동 제출하지 않는다.
- 글자 수 `0 / 500` 표시
- 추천 버튼은 명확한 검정 배경/흰 글자 스타일
- 제출 중 버튼 비활성화 및 “취향 분석 중…” 표시

### 추천 결과
- 결과 제목과 “취향 매칭 점수(상대 점수)” 설명
- 최대 3개의 카드
- 1위는 순위 숫자와 점수를 가장 눈에 띄게 표현하되 과도한 장식은 피한다.
- 카드 구성: 순위, 작품명, 공개연도/장르(데이터가 있을 때만), 백분율, 진행 막대, 분석 이유
- 점수 막대는 `role="progressbar"`와 `aria-valuenow`, `aria-valuemin`, `aria-valuemax` 제공
- 포스터가 없는 경우 깨진 이미지 아이콘이나 빈 이미지 상자를 만들지 않는다.

### 피드백
- 추천 영역과 명확히 구분되는 하단 섹션
- 선택적 이름 입력 + 피드백 textarea + 전송 버튼
- 최신순 목록에 이름/익명, 작성일, 내용 표시
- 긴 텍스트는 레이아웃을 깨지 않도록 줄바꿈 처리
- 빈 목록은 “아직 등록된 피드백이 없습니다.” 표시
- 로딩/오류 상태를 별도로 표시

## 4. 반응형 기준
- 모바일 우선으로 작성
- 320px 너비부터 가로 스크롤 없이 콘텐츠가 표시되어야 한다.
- 넓은 화면에서는 본문 최대 너비를 제한하고 중앙 배치한다.
- 추천 카드는 데스크톱 1열 또는 2열 중 콘텐츠 가독성이 높은 구성을 선택하되, 순위가 읽히는 순서를 유지한다.
- 모바일에서는 카드 1열, 입력창/버튼은 화면 너비에 맞춘다.
- 터치 대상은 충분한 높이와 간격을 확보한다.

## 5. 접근성
- 모든 입력에는 실제 label을 연결한다.
- 버튼은 `<button>` 요소를 사용한다.
- 키보드 포커스가 명확하게 보이도록 `:focus-visible`을 구현한다.
- 색상만으로 순위나 오류를 구분하지 않는다.
- 상태 메시지는 적절한 `aria-live="polite"` 영역에 표시한다.
- 의미 있는 제목 계층(h1, h2, h3)을 유지한다.
- 애니메이션은 필수 아님. 사용할 경우 `prefers-reduced-motion`을 존중한다.

## 6. 완료 기준
- 첨부 이미지의 흑백 미니멀 방향성이 반영됨
- 서비스명이 명확하고 입력→추천→피드백 순서가 자연스러움
- 1~3위 및 점수·이유가 빠르게 구분됨
- 로딩/빈 상태/오류 상태가 디자인에 포함됨
- 모바일 320px, 태블릿, 데스크톱에서 레이아웃이 깨지지 않음
- 키보드 포커스 및 스크린리더 상태 안내가 동작함
