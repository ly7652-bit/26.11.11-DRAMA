# 04. 백엔드 및 OpenAI 구현 지침

## 1. API 함수
Vercel Node.js Functions로 다음 엔드포인트를 만든다.
- `POST /api/recommend`
- `GET /api/feedback`
- `POST /api/feedback`

요청 메서드가 맞지 않으면 `405 METHOD_NOT_ALLOWED`를 반환한다. JSON이 아니거나 파싱할 수 없으면 `400 INVALID_JSON`을 반환한다.

## 2. 추천 API 처리 순서
1. 메서드 확인
2. JSON 파싱
3. preference 문자열 검증(5~500자)
4. 서버 측 요청 제한 적용
5. OpenAI API 호출
6. 모델 응답을 JSON으로 파싱
7. 자체 스키마 검증 및 중복 작품 제거
8. 순위 재정렬(점수 내림차순, 동점이면 모델이 반환한 순서 유지)
9. 최대 3개로 제한
10. 정해진 응답 JSON 반환

## 3. AI 출력 스키마
서버 내부에서 다음 구조를 기대한다.
```json
{
  "recommendations": [
    {
      "title": "string",
      "year": 2020,
      "genres": ["string"],
      "matchPercentage": 85,
      "reason": "string"
    }
  ]
}
```
제약:
- recommendations 배열은 0~3개
- title: 공백 제거 후 1~120자
- year: 정수, 1900~현재 연도+2 또는 `null`
- genres: 최대 5개, 각 1~30자
- matchPercentage: 정수 0~100
- reason: 20~500자
- 중복 title은 대소문자/공백 정규화 후 제거
- 필수 필드 누락 또는 잘못된 타입이면 해당 항목을 제외하거나 전체 응답을 안전하게 실패 처리한다. 잘못된 데이터를 그대로 반환하지 않는다.

## 4. 프롬프트 지침
시스템 지침은 다음 원칙을 포함한다.
- 사용자의 취향을 장르, 분위기, 소재, 전개 속도, 감정 톤으로 해석한다.
- 실제 존재하는 드라마만 추천하도록 노력한다.
- 작품명/연도 등 사실을 확신할 수 없으면 추측하지 말고 제외하거나 연도를 null로 반환한다.
- 추천 이유는 사용자의 표현과 작품의 알려진 특징을 연결해 구체적으로 작성한다.
- 최대 3개만 반환하고 불필요한 서론/마크다운을 출력하지 않는다.
- 백분율은 객관적인 확률이 아니라 후보 간 상대적 취향 적합도를 표현하는 휴리스틱 점수임을 전제로 한다.
- JSON 외 텍스트를 출력하지 않는다.
서버가 모델 출력의 형식과 값 범위를 반드시 재검증한다. 프롬프트만으로 안전성을 보장하지 않는다.

## 5. 모델과 API 사용
- 모델명은 환경 변수 `OPENAI_MODEL`로 설정한다.
- OpenAI 공식 SDK를 사용한다.
- 지원되는 경우 구조화 출력/JSON 스키마 기능을 사용하되, 서버 측 검증을 생략하지 않는다.
- 토큰 상한과 요청 타임아웃을 설정해 과도한 응답 비용을 방지한다.
- 모델명, 프롬프트, SDK 옵션은 현재 설치한 SDK 버전과 공식 문서에 맞춰 구현한다. 존재하지 않는 옵션을 추측해 사용하지 않는다.

## 6. 오류 처리
권장 상태 코드:
- 400: `INVALID_INPUT`, `INVALID_JSON`
- 405: `METHOD_NOT_ALLOWED`
- 429: `RATE_LIMITED`
- 500: `SERVER_CONFIG_ERROR`, `AI_RESPONSE_INVALID`
- 502: `AI_PROVIDER_ERROR`
- 504: `AI_TIMEOUT`

클라이언트에 공급자 내부 오류, 스택, 키, 프롬프트 전문을 노출하지 않는다. 서버 로그에는 오류 종류와 요청 식별 정보만 기록하고 API 키/개인정보는 기록하지 않는다.

## 7. 보안과 비용
- OpenAI 키는 `OPENAI_API_KEY` 서버 환경 변수에만 저장
- 사용자 입력 길이 및 요청 횟수 제한
- 타임아웃과 최대 출력 토큰 설정
- 동일 출처 요청만 기본 허용
- 사용자 입력을 시스템 지침으로 승격하지 않는다. 사용자 문장은 분석 대상 데이터로 취급한다.
- API 키를 Git, 브라우저 번들, 응답 헤더/본문, 로그에 노출하지 않는다.

## 8. 완료 기준
- 입력 검증, OpenAI 호출, JSON 검증, 오류 코드가 구현됨
- 정상 응답은 최대 3개, 순위는 1~3위
- 점수는 0~100 정수
- reason이 비어 있지 않음
- OpenAI 장애 시 화면에 일반 오류 메시지 제공
- 키 누락 시 명확한 서버 설정 오류 처리
